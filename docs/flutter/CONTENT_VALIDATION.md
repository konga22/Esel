## 자동 검증

- `flutter analyze --no-pub` 경고 없음, `flutter test --no-pub` 150개 통과. 새 테스트는 `test/features/challenges/`의 기간·하루 한 호·계정/소유권·삭제 연결 정리·원자적 재조회·기존 JSON 호환·원격 무자동전환·화면 진입·오류 재시도·비교 흐름.
- 기존 가입→창간→발행, 초안 편집/저장/취소, 오늘의 후보 3색·서울 자정, P01·P18 검사를 함께 실행한다.

## 직접 실행과 미검증 구분

- Windows에서 Android x64 debug APK 빌드 성공. 기존 Pixel_9는 /data 용량 부족으로 설치가 실패했다. Flutter run이 설치 실패 뒤 기존 앱 제거/재설치를 자동 시도한 로그가 있어 기존 에뮬레이터 앱 데이터의 보존 여부는 확인하지 못했다. 해당 기기 초기화나 DB 삭제 명령은 실행하지 않았다.
- 기존 기기를 계속 건드리지 않고 작업 폴더 밖 저장소와 분리된 `.esel-tools/content-avd`에 8GB 테스트 AVD를 만들었다. emulator-5556에 APK 설치·앱 시작 성공.
- 처음 JNI 등록 누락으로 Flutter 로고에 멈췄다. Windows pub get이 symlink 단계에서 중단돼 Android GeneratedPluginRegistrant 생성이 빠진 환경 문제였다. 해당 프로세스에서만 `FLUTTER_WINDOWS=false`로 pub get을 완료하고 다시 빌드하여 해결. 전역 설정이나 패키지 버전을 바꾸지 않았다.
- 네이티브 UI는 computer-use로 이메일 가입·실제 앨범 사진 선택·제호/얼굴 위치 편집·창간호 발행·내 잡지·주간 주제에 기존 호 연결을 확인했다. 기기 저장 파일은 issueNumber=1, challengeId=2026-10-12:weekly였다. 같은 옷 비교는 과거 발행본을 준비한 자동 앱 테스트로 검증했으며 Android 수동 비교는 미검증이다. 세부 추가 결과는 아래 표와 PR 기록을 따른다.
- IAB 브라우저의 localhost 접속은 시간 초과로 목업 수동 조작을 완료하지 못했다. 목업 캡처의 시각 확인과 실제 Flutter 조작/위젯 테스트는 구분한다. 목업 전체를 직접 눌러 확인했다고 주장하지 않는다.
- macOS·iOS·물리 Android·실제 OAuth·Docker·DB·서버 API·공개 커뮤니티 목록은 미검증/범위 밖. Kotlin Gradle Plugin의 향후 Flutter 호환 경고는 남아 있으며 이번에 관련 라이브러리를 교체하지 않았다.

두 콘텐츠에 참여할 이유와 방법이 드러나도록 가판대/내 잡지에 진입점을 연결하고, 주제·기간·참여 상태와 내 표지를 확인하는 화면을 추가했습니다. 오늘 이미 발행한 경우에는 새 호를 만들지 않고 오늘 표지를 연결합니다. 지난 코디 선택에는 본인 과거 발행본의 날짜와 미리보기를 넣었습니다. 자동 화면 검사에서 발견한 좁은 화면의 날짜 넘침과 Windows 사진 경로 문제도 수정했습니다. 앱의 직접 조작 확인 범위와 자동 테스트 범위는 PR/검증 문서에 구분했습니다. 목업 전체 동선·물리 휴대폰·macOS/iOS·사진 권한 조합은 후속 확인이 필요하며, 서버 인증/동기화/커뮤니티 참여 목록은 아직 구현 완료가 아닙니다.
