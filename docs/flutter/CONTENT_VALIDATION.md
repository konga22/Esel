## 창간 얼굴 연출 후속 수정 (2026-10-17)

- 재현: 얼굴 위치를 지정하지 않고 `물감 한 획`/`목 아래`를 선택하면 임의 기본 좌표에 연출을 적용했다. 목 아래에서는 탭도 막혀 다른 모드로 돌아가야 했고, 확대 상한과 세로 보정 때문에 턱 아래 공간이 적은 사진에서 얼굴이 다시 나타날 수 있었다.
- 수정: 창간 J6에서 위치 지정 전에는 제호·물감·자르기를 적용하지 않은 사진을 보여 준다. 선택한 모드는 유지하며 얼굴 가운데를 누른 뒤 적용한다. 위치 다시 정하기와 얼굴 크기 조절을 제공하고 크기는 발행 표지에도 전달한다. 제호는 공통 미리보기의 크기 계산을 재사용한다. 잘못된 기본 좌표를 실제 얼굴 표시처럼 보여 주던 원도 제거했다.
- 공통 목 아래 계산: 턱을 표지 위쪽에 유지한다. 아래 공간이 적으면 필요한 만큼 확대하고, 턱 아래 사진 자체가 없으면 빈 배경을 남긴다. 얼굴을 다시 내려서 빈 곳을 채우지 않는다. 디자인 생성기의 기존 확대 상한과 다른 부분은 이 재현 오류를 고치기 위한 앱 보정이다. 자동 얼굴 인식이나 익명화 보장은 추가하지 않았다.
- Android API 37 별도 테스트 AVD에서 앨범 사진 선택 → 제호 입력 → 얼굴 지정 → 물감 눈 부위 적용 → 목 아래 얼굴 잘림을 직접 확인했다. [물감 실제 화면](evidence/20261017/android-founding-paint.png), [목 아래 실제 화면](evidence/20261017/android-founding-neck.png). 이 후속 수정에서 새 계정 생성/실제 발행은 하지 않았으며 창간·발행 연결은 자동 위젯 테스트로 검증했다.
- 회귀 검증: 전체 Flutter 테스트 156개, 정적 분석, 제품 규칙 60개, 하네스 검사, 디자인/목업/개발 문서 생성, 디자인 캡처 통과. 기존 저장 사진·발행 기록·서버 코드는 변경하지 않았다. macOS/iOS·실물 휴대폰은 미검증이다.

- 일반 표지 편집에서 원본 위치 지정을 연 뒤 효과 버튼을 누르면, 칩은 선택되지만 `_locatingFace`가 true로 남아 공통 미리보기가 효과를 모두 숨기는 오류를 위젯 테스트로 재현했다(기대 false, 실제 true). 효과 선택 시 원본 모드를 종료하도록 수정한 뒤 동일 재현 테스트가 통과했다.

### 추가 로컬 검토본: 중복 연출·제호 크기 (PR 미반영)

- 앞선 창간 수정의 숨김 방식을 사용자 요청으로 변경했다. 얼굴 연출 버튼은 위치 지정 전에도 즉시 미리보기에 적용한다. 원본에서 좌표를 잡는 동작은 `얼굴 위치 맞추기`로 분리했다. 위치 조정 취소는 기존 좌표와 확인 상태를 유지한다.
- 물감·제호 뒤로·목 아래는 독립적으로 켜고 끈다. 그대로는 전체 해제다. 목 아래 자르기를 함께 켜면 얼굴과 그 위의 가림이 표지 밖에 있을 수 있으며 이를 안내한다. 기존 단일 효과 읽기용 `faceMode`도 선택 상태와 일치하도록 유지한다.
- 창간 이름 단계와 일반 표지 편집에서 50~140% 제호 크기 조절을 제공한다. `faceEffects`와 `mastheadScale`을 초안/발행 데이터에 저장하고 공통 미리보기·로컬 공개 모델로 전달한다. 옛 JSON에 새 필드가 없으면 기존 단일 효과와 100% 크기를 유지한다. 서버 API/DB는 수정하지 않았다.
- 자동 검사: 전체 Flutter 테스트 160개, 정적 분석, 하네스 정합성, 제품 규칙 60개 통과. 다중 선택/해제·제호 크기 발행 전달·위치 조정 취소·이전/신규 JSON 복원을 포함한다.
- 수동 확인은 APK 설치 후 사진 선택 단계에서 사용자의 컴퓨터 조작 중단 요청으로 멈췄다. 이번 다중 연출과 크기 조절을 Android에서 끝까지 직접 검수했다고 주장하지 않는다. 이후에는 마우스/키보드/창 활성화 없이 백그라운드 검사와 APK 빌드만 수행했다. macOS/iOS는 미검증이다. 커밋·푸시·PR 갱신은 하지 않았다.

메시지 A

교수님께서는 ESEL에 콘텐츠 보강이 필요하다고 말씀하시며 월·연간 패션 베스트 선정을 예시로 제안하셨습니다. 팀 회의에서는 베스트 선정과 공개 인기 순위를 제외하고, ‘주간 드레스코드’와 ‘같은 옷, 다른 코디’ 두 가지를 추가하기로 결정했습니다. 이번 개발은 서버 연결 전 단계로, 기존 발행 흐름과 하루 한 호 규칙을 유지하면서 기기 내부에서 참여·연결·저장·조회를 할 수 있게 하는 범위입니다. 기존 서버 코드는 보존하고 데이터·권한·오류 계약 검토안을 남겨 추후 실제 API 연결을 이어갈 예정입니다.

메시지 B

두 콘텐츠에 참여할 이유와 방법이 드러나도록 가판대/내 잡지에 진입점을 연결하고, 주제·기간·참여 상태와 내 표지를 확인하는 화면을 추가했습니다. 오늘 이미 발행한 경우에는 새 호를 만들지 않고 오늘 표지를 연결합니다. 지난 코디 선택에는 본인 과거 발행본의 날짜와 미리보기를 넣었습니다. 자동 화면 검사에서 발견한 좁은 화면의 날짜 넘침과 Windows 사진 경로 문제도 수정했습니다. 앱의 직접 조작 확인 범위와 자동 테스트 범위는 PR/검증 문서에 구분했습니다. 목업 전체 동선·물리 휴대폰·macOS/iOS·사진 권한 조합은 후속 확인이 필요하며, 서버 인증/동기화/커뮤니티 참여 목록은 아직 구현 완료가 아닙니다.
