# Flutter 핵심 서버 API 연결

> **사진 업로드 작업 중:** 사인 글자를 빼면 가렸던 얼굴이 드러날 수 있어 ‘사인 뒤로’의 서버 업로드를 보류한다(2026-10-19 사용자 확인). 기존 기기 미리보기·로컬 기록은 유지한다. 이유·해제 조건·인계 사항은 [사진 연결 결정 기록](MEDIA_UPLOAD_HANDOFF.md)을 먼저 확인한다.

## 이번 작업 범위

서버 모드와 로컬 시연은 같은 화면·화면 전환을 쓴다. `ESEL_API_MODE`로 ServiceLocator에서 소스를 선택한다. 별도 DeviceHomeScreen·Server*Screen은 제거했으며 기존 HTTP 클라이언트·토큰·서버 소스는 보존했다.

데이터는 각 기능의 domain 모델·data 소스·presentation 화면으로 나눈다. 기존 AppHttpClient의 토큰·오류 처리를 재사용한다. 공개 목록은 서버가 준 항목만 표시하며 잠긴 표지를 기기 자료에서 보충하지 않는다. 반응 숫자는 소유자용 API 화면에만 있고, 공개 모델에는 숫자를 두지 않는다. 목록과 독자 한 줄은 cursor로 다음 페이지를 받는다.

로그인·가입 429 RATE_LIMITED(2026-11-23): 서버는 같은 이메일로 1분 안에 5번 시도하면 그 1분 동안 맞는 비밀번호도 막는다(서버 #35). 앱은 "로그인 시도가 너무 많아 잠시 막혔어요. 1분 뒤 다시 시도해 주세요."(가입은 "가입 시도가…")로 알리고 세션을 만들지 않는다(`auth/domain/auth_failure_message.dart`, 테스트 `real_auth_test.dart`). 1분은 서버 `WINDOW_MS`와 같고, 서버가 바꾸면 이 문구도 고친다.

Apple·Google 로그인 주소 정리(2026-11-25): `AuthRemoteSource`에 남아 있던 `/auth/google`·`/auth/apple` 호출을 지웠다. 서버 약속에 없는 주소이고, 서버 모드에서는 저장소가 `OAUTH_NOT_CONFIGURED`로 먼저 막아 부르는 곳이 없었다(#27 "앱 쪽에서 맞출 것"). 서버 모드에서 버튼을 숨기는 것과 mock 모드의 기기 시연 계정은 그대로다. 도입 시점이 정해지면 약속에 주소를 먼저 더한 뒤 다시 만든다. 테스트 `real_auth_test.dart`의 "unconfigured social auth never calls an API" 검사가 서버 모드에서 API를 부르지 않는 것을 계속 확인한다.

실패한 요청은 오류·재시도를 표시한다. 서버 응답 전 좋아요·구독·복원을 완료했다고 표시하지 않는다. 댓글 실패 시 입력을 유지한다. 계정이 바뀌면 열린 서버 상세 화면을 닫고 새 계정 키로 오늘 화면을 다시 만든다.

DEV-25(미술 도구 용어·198×60의 바뀌는 칸 3칸 캡슐), DEV-12 공통 팔레트, DEV-13 세로 스케치북과 DEV-24 로컬 착용 정보를 반영했다. 서버 API 경로·권한·DB migration은 바꾸지 않는다. 서버 errors.ts의 화면 문구만 새 용어로 맞춘다.

## 동일 화면과 데이터 출처

- `TodayController`: 로컬 기록 또는 TodayRemoteSource/MagazineRemoteSource. 프로필을 만들기 전에는 오늘의 색만 조회하며 스케치북 404가 가입을 막지 않는다.
- `StandController → StandSource`: 공통 팔레트. 추천은 미구독자의 최신 공개 표지, 구독은 구독한 사람만, 색상은 기존 잠금 규칙을 적용한다. 로컬 비후보 색 순서는 고정 물감 순서이며 실제 선택량이라고 설명하지 않는다.
- `MagazineController → MagazineSource`: 본인/타인 모두 ShelfScreen. 원격은 서버 공개 항목과 cursor만 사용한다.
- `ReactionsController`: 공통 IssueBottomSheet의 상세·반응·한 줄을 로컬/원격으로 처리한다. 댓글 저장에 성공한 뒤 목록 조회만 실패하면 재시도는 조회만 한다.
- `ScrapsController → ScrapsRemoteSource`(서버 모드만): 내 스케치북 저장함 탭을 열 때마다 `GET /me/scraps`를 다시 읽는다. 처음에만 빈 로딩을 쓰고 다시 읽는 동안에는 받은 목록을 유지한다. 서버가 준 캔버스만 그리며(잠긴·삭제·차단은 서버가 뺌, P01) 기기 예시로 채우지 않는다. 응답과 모델에 반응 숫자가 없다(P18). 자세히 보기에서 저장을 취소하면 다시 읽기 전에도 목록에서 뺀다. 다음 페이지 실패는 기존 목록과 cursor를 유지하고, 계정이 바뀌면 이전 계정 목록과 늦게 온 응답을 버린다. mock 모드는 기존 기기 보관 저장함을 그대로 쓴다.
- `FriendsController → FriendsSource`(DEV-16, 2026-11-26): mock은 `FriendsMockSource`(기존 예시 친구·요청), 서버는 `FriendsRemoteSource`. 로그인하면 친구 목록을 읽어 마이페이지 숫자 줄에 쓰고, 친구 화면을 열 때마다 목록과 받은 요청을 다시 읽는다. 전체 수는 마지막 페이지까지 받았을 때만 숫자로 보이고, 모르면 '–'. 서버 모드에서는 트윈이 아직 연결되지 않아 친구 칸 이름을 '친구'로 하고 친구 화면의 트윈 줄을 숨긴다. 서버 응답에는 사진·소개가 없어 사인 첫 글자 원과 "○○부터 친구"(서울 날짜)로 보인다. 수락·나중에는 서버가 답한 뒤에만 목록을 바꾸고 처리 중에는 버튼을 막는다. 이미 처리된 요청(404)은 안내하고 목록에서 뺀다. 친구 찾기는 요청을 보내기 전에 사인 규칙(P14)·나 자신·이미 친구·이미 받은 요청을 앱에서 거른다. 이미 받은 요청은 서버가 두 사람 사이 요청을 하나만 두어 409가 나므로 수락을 안내한다. 서버 오류는 `NOT_FOUND` → "찾지 못했어요. 사인 철자를 확인해 주세요."(합격 기준), `REQUEST_EXISTS` → 이미 요청이 있음, `ALREADY_FRIENDS` → 이미 친구로 바꾸고, 실패하면 철자를 고칠 수 있게 시트를 열어 둔다. 계정이 바뀌면 이전 계정 목록과 늦게 온 응답을 버린다. #44 리뷰 반영: 계정 전환 숫자와 다시 읽기 숫자를 나눴다. 다시 읽기가 시작되면 진행 중이던 더 보기는 무효로 하고 버튼을 바로 풀며, 그 응답은 새 목록에 섞지 않는다. 수락·나중에는 계정만 비교해 다시 읽기 중이어도 서버 결과를 반영하고, 처리 중 표시는 `finally`에서 푼다(전에는 다시 읽기가 끼어들면 "불러오는 중"·버튼 막힘이 영원히 남았다). 테스트 `test/features/friends/friends_test.dart`, `test/features/magazine/my_page_test.dart`(DEV-16). 차단한 사람의 검색 노출(DEV-16 미정)은 서버 응답을 그대로 따른다.
- `BlocksController → BlocksSource`(DEV-20 차단, 2026-11-26): mock은 `BlocksMemorySource`, 서버는 `BlocksRemoteSource`. 자세히 보기 ··· 시트의 "차단하기"는 전에는 아무것도 하지 않으면서 "차단했습니다. 피드와 팔레트에서 제외됩니다."라고 안내했다. 이제 확인 대화상자를 거쳐 `POST /users/:masthead/block`을 부르고, 서버가 답한 뒤에만 "○○ 님을 차단했어요."라고 안내한다. 성공하면 열린 시트를 닫고, 그 사람의 스케치북을 보고 있었다면 홈으로 돌아간다. 차단·풀기에 성공하면 홈·팔레트를 다시 읽는다(서버가 차단한 사람을 응답에서 빼므로). 내 캔버스에서는 차단 항목을 숨긴다(서버도 나 자신은 404). 설정 > 차단한 사람은 `GET /me/blocks`를 열 때마다 읽고 숫자 없이 목록·차단한 날(서울)·풀기를 보인다. 풀기는 서버가 답한 뒤에만 뺀다. 로딩·빈 화면·오류(다시 시도)·더 보기가 있고, 계정이 바뀌면 이전 계정 목록과 늦은 응답을 버린다. 친구 #44 리뷰와 같은 문제를 미리 막았다: 계정 전환 숫자와 다시 읽기 숫자를 나눠, 다시 읽기가 끼어들어도 더 보기·풀기 처리 중 표시가 남지 않고 서버가 처리한 풀기는 반영한다. mock 모드는 시연 피드를 거르지 않으므로 "차단했다" 대신 목록에만 담는다고 안내한다. 신고 항목은 이번 범위가 아니며 아직 서버를 부르지 않는다(처리 기준 미정). 테스트 `test/features/moderation/blocks_test.dart`. 이 화면들은 디자인 보드에 아직 없다(DEV-20 "먼저 디자인 보드에 추가" 항목은 남음).

### 친구 실서버 확인 (2026-11-26)

로컬 Docker 서버(`docker compose up -d --build api`)에 이번에 새로 만든 테스트 계정 A·B·C로만 확인했다. 기존 계정·시연 데이터는 바꾸지 않았다.

| 확인 | 결과 |
|---|---|
| API: 없는 사인으로 요청 | `404 NOT_FOUND` |
| API: A→B 요청, 같은 요청 다시 | `201`, 다시 보내면 `409 REQUEST_EXISTS` |
| API: B→A 역방향 요청(A가 이미 보냄) | `409 REQUEST_EXISTS`. 앱이 이 경우를 보내기 전에 거르고 수락을 안내하는 근거 |
| 에뮬레이터(서버 모드, B로 로그인) | 로그인 시트에 이메일만(Apple·Google 없음). 마이페이지 숫자 줄 `0 친구` → 나의 친구 화면에 A의 받은 요청, 트윈 줄 없음 |
| 친구 찾기에 없는 사인 | 시트 안에 "찾지 못했어요. 사인 철자를 확인해 주세요.", 시트 유지 |
| 친구 찾기에 A의 사인 | 서버에 보내지 않고 "○○ 님이 이미 요청을 보냈어요. 받은 친구 요청에서 수락해 주세요." |
| 수락 | "○○ 님과 친구가 되었어요." 후 나의 친구 (1), "2026. 11. 26.부터 친구". API로 A의 친구 목록에도 B가 있음 |
| C에게 요청 보내기 | "○○ 님에게 친구 요청을 보냈어요." 후 API로 C의 받은 요청에 B가 있음 |
| 마이페이지로 돌아오기 | 숫자 줄 `1 친구` |

나중에(거절)는 가짜 HTTP·위젯 테스트로만 확인했다.
- `ReportsSource`(DEV-20 표지 신고, 2026-11-26): mock은 `ReportsMemorySource`, 서버는 `ReportsRemoteSource`(`POST /issues/:id/reports`). 자세히 보기 ··· 시트의 신고 항목은 전에는 서버를 부르지 않으면서 "신고가 접수되었습니다. 검토 후 조치됩니다."라고 안내했다. 이제 사유(스팸·광고 / 괴롭힘·혐오 표현 / 부적절한 사진·내용 / 기타, 서버 `spam`·`harassment`·`inappropriate`·`other`)를 하나 고르고 내용(선택, 500자)을 덧붙여 보내며, 서버가 접수한 뒤에만 신고 시트 안에서 "신고를 접수했어요."를 보인다. 결과를 하단 알림으로 띄우지 않는 이유는 신고 시트가 자세히 보기 시트 위에서 열려 하단 알림이 그 뒤에 가려지기 때문이다(에뮬레이터에서 확인). 처리 주체·기준은 미정이라 "검토 후 조치" 같은 약속은 하지 않는다. 실패하면 시트를 열어 둔 채 이유를 보인다(`RATE_LIMITED` → 1분 뒤 다시, `NOT_FOUND` → 볼 수 없는 캔버스). 내 캔버스와 로그인 전에는 신고·차단을 할 수 없어 ··· 버튼을 숨기고, 버튼은 48×48로 키웠다(전에는 36). mock 모드는 이 기기에만 담는다고 안내한다. 독자 한 줄 신고는 한 줄마다 신고할 화면 요소가 없어 이번 범위가 아니다. 테스트 `test/features/moderation/reports_test.dart`.
- `RecordsSource`: 같은 MonthlyRecordScreen에서 월 이동·빈칸 복원. 로컬 복원도 계정별 저장·월 2회·서울 날짜·그날 후보를 검사한다.
- `CoverDraft.garments`는 선택 필드다. 기존 저장본에는 빈 목록을 적용한다. 옷 종류·이름(선택, 40자)·메모·오늘의 색 표시·원본 사진 비율 좌표를 저장한다. 사진 교체 시 태그 위치를 지우고, 옷 재사용 시 동일 ID를 쓰되 위치·오늘의 색은 다시 지정한다. 내 옷은 계정별로 분리되며 탈퇴 시 함께 지운다. 가격·상품 URL 필드는 없다.

## 서버 담당자와 남은 연결 작업

팔레트 추천/구독과 garments는 기존 서버 DTO·계약을 사용한다. 본인 옷 목록 `GET /me/garments`의 `id`를 읽고 실제 내 옷으로 확인한 UUID만 재사용한다. 새 옷의 기기 ID는 보내지 않는다. 새 endpoint·migration은 추가하지 않았다. 팔레트 색 순서 등 남은 검토안은 기능 목록을 따른다.

홈 피드(로그인 `GET /feed`, 비로그인 `GET /today/cover`)와 팔레트(`/palette/recommended`·`/palette/subscriptions`·`/stand?colorId=`)는 연결했다. 사진 ID를 인증된 미디어 조회로 연결하고, 얼굴 연출을 적용한 사진의 업로드 모듈을 추가하는 중이다. 새 캔버스 발행은 서버 #33의 `faceCrop`·`paintStroke` 요청·응답을 사용하도록 맞췄다. #33이 병합된 최신 main을 작업 브랜치에 통합했으며, 구형 서버의 faceMode 계약으로 자동 전환하지 않는다. 사인 뒤로는 계속 차단한다. 착용 정보 동기화와 팔레트 색 순서(`/palette/colors`) 연결도 남아 있다. 같은 색 인원은 서버가 `/palette/colors` 항목의 `count`나 `/stand`의 `total`을 주면 표시하고, 없으면 숫자 없이 색 이름만 보인다. 서버 사진은 목록에서 thumb·피드와 상세에서 original을 메모리로 조회한다. 사진 404는 ‘사진 제공 준비 중’, 다른 조회 실패는 재시도를 표시하며 원격 미구현 기능은 오류로 표시한다. 이미 얼굴 연출이 적용된 서버 사진에 물감·자르기를 다시 적용하지 않는다. 서버 모드의 올리기는 사진 합성·업로드 완료 후 실제 POST /issues를 호출한다. 중복 발행·사진 미완료 오류를 안내하며 성공 후 재조회한다. 상세는 [발행 연결 기록](PUBLISH_API_CONNECTION.md)에 있다. 친구/트윈의 예시 화면과 미연결 이번 주 주제·전시는 서버 모드 진입에서 제외한다. 서버 실패 시 로컬 전환은 없다.

## 실행 방법

Flutter 3.44.0 / Dart 3.12.0, Node는 저장소 기준 버전을 사용한다. 새 Flutter 패키지는 추가하지 않았다. 저장소 루트에서 Docker Desktop의 Linux 엔진을 시작한 뒤:

```sh
docker compose up -d --build api
cd flutter_app
flutter pub get
flutter run -d <장치ID> --dart-define=ESEL_API_MODE=server --dart-define=API_BASE_URL=http://10.0.2.2:3000/api
```

위 주소는 Windows/macOS의 Android 에뮬레이터에서 쓴다. USB Android 실기기는 `adb reverse tcp:3000 tcp:3000` 후 주소를 `http://127.0.0.1:3000/api`로 바꾼다. macOS의 iOS 시뮬레이터는 호스트 주소와 Xcode 환경을 따로 확인해야 하며 이번 검수에서는 실행하지 않았다. 네트워크 오류가 나면 Docker·주소를 확인하고 앱의 재시도 버튼을 누른다. 기존 로컬 발표 시연은 `--dart-define=ESEL_API_MODE=mock`을 명시한다.

처음 설치한 서버 DB에는 다른 사람의 표지가 없을 수 있다. 로그인/가입 후 첫 캔버스 흐름에서 사인을 저장하고 스케치북에서 오늘의 색을 고른다. 스케치북의 원격 기록과 만들기의 기기 초안은 구분한다. 사진이 있는 기기 초안을 서버 발행본으로 가장하지 않는다.

## 남은 계약과 화면 차이

- **사진·발행:** 사진은 IssueMediaDto의 id와 확정된 `/media/:id` 계약으로 조회한다. 업로드 모듈은 준비→바이너리 PUT→READY 확인 순서이며 원본 대신 얼굴 연출이 적용된 PNG를 사용한다. 사인 뒤로 업로드는 얼굴 노출 가능성 때문에 보류한다. #34 리뷰에 따라 새 faceCrop·paintStroke로 통일했다. POST 뒤 응답을 놓친 경우 같은 mediaId의 당일 발행을 확인하면 성공으로 복구한다. [발행 연결 기록](PUBLISH_API_CONNECTION.md)에 검증 범위와 JPEG 미적용 사항을 구분했다. 자세한 진행·검증 상태는 [인계 기록](MEDIA_UPLOAD_HANDOFF.md)을 따른다.
- **과거 후보 색:** 특정 지난 날짜 후보를 조회하는 API는 아직 없다. 복원창은 12색을 선택지로 보여주고 그날 후보인지 서버가 검사한다. 후보 밖 색·마감·월 2회 초과는 오류로 안내한다. 임시 날짜 배정 알고리즘을 앱에서 서버 정답처럼 사용하지 않는다. 정확히 3색만 보여주려면 서버 담당자와 조회 계약을 합의해야 한다.
- **사인·표시:** 공통 스케치북의 원격 소스는 사인을 탐색 키로 쓴다. 공개 DTO에 없는 내부 사용자 ID를 만들지 않는다. 로컬 공개 항목에는 기존 ownerId를 쓴다.
- **시각 검수:** 기존 토큰·글꼴과 앱 화면을 사용하되, 사진을 받지 못한 목록은 재시도 안내를 표시한다. Windows의 Android 에뮬레이터에서 실제 Docker 사진 업로드·조회와 정상 앱 화면을 검수했다. 실제 기기·macOS·iOS는 미검증이며 자세한 범위는 사진 인계 기록을 따른다.

### 탈퇴 DELETE /me 실서버 확인 (2026-11-23)

앱의 탈퇴 경로(`AuthRemoteSource.deleteAccount` → `DELETE /me {confirmed: true}` → 기기 토큰 삭제)를 로컬 서버(NestJS + Docker PostgreSQL)에서 **새로 만든 테스트 계정으로만** 확인했다. 기존 계정·데이터는 지우지 않았다.

재현(PowerShell, 저장소 루트). 준비 도구는 서버 API만 써서 테스트 계정 두 개를 만들고, 검사는 그중 탈퇴자 하나만 지운다. 출력되는 fixture 파일에 임시 비밀번호가 있으니 커밋하지 않는다.

```powershell
$env:ESEL_DELETE_FIXTURE = node flutter_app/tool/prepare_account_delete_fixture.mjs
cd flutter_app; flutter test --no-pub test/features/auth/account_delete_live_test.dart
```

| 확인 | 결과 |
|---|---|
| 실서버 검사 `account_delete_live_test.dart` | 통과. 탈퇴 뒤 기기 토큰 없음, 같은 이메일·비밀번호 로그인은 `401 WRONG_CREDENTIALS`, 다른 사람에게 그 캔버스·스케치북·사진은 `404`, 다른 사람 저장함에서 빠짐, 탈퇴자 사인은 다시 쓸 수 있음 |
| DB 행(탈퇴자 기준) | 계정·프로필·캔버스·미디어·알림 설정·옷·그 캔버스의 저장·좋아요·한 줄·구독·로그인 세션이 모두 1 → 0. 전체 사용자 수는 탈퇴자 한 명만 줄어듦 |

| 확인 체크 전 | 탈퇴 진행하기를 눌러도 다음 단계가 열리지 않음(기능상 막힘) |
| 두 번 확인 | 확인 체크 + "계정 삭제 최종 확인" 대화상자(되돌릴 수 없음 안내)로 두 번 |

확인하다 찾은 앱 문제와 고친 내용(같은 날 고침, 테스트 `test/features/settings/account_delete_test.dart`):

1. **서버 실패 시 안내 없음 → 고침.** 전에는 서버를 끈 상태에서 영구 삭제를 누르면 대화상자만 닫히고 화면에 아무 안내가 없었고, 로그에 `Unhandled Exception: NetworkFailure (OFFLINE)`가 남았다. `AuthController.deleteAccount`에 실패 처리가 없어 로딩 상태도 풀리지 않았다. 이제는 실패하면 로딩을 풀고 로그인을 유지한 채 오류를 다시 던지고, 설정 화면이 이유를 한 줄로 알린 뒤 계정 관리에 머문다(다시 시도 가능). 탈퇴 중에는 버튼이 "탈퇴하는 중…"으로 막히고 확인 체크도 바꿀 수 없다. 기기 초안 삭제(`app.dart`의 `_deleteAccount`)는 서버 탈퇴가 성공한 뒤에만 실행된다. 에뮬레이터에서 서버를 끈 채 다시 확인했다: 안내가 뜨고 처리되지 않은 오류 로그 0건, 서버를 켠 뒤 같은 화면에서 탈퇴 성공.
2. **체크 전 버튼이 비활성으로 보이지 않음 → 고침.** 탈퇴 진행하기는 눌러도 아무 일이 없게만 막혀 있고 모양은 체크 후와 같았다. 이제 확인 체크 전과 탈퇴 중에는 `EselButton(enabled: false)`로 비활성 모양(흐린 글자)이 되고 눌리지 않는다. DEV-19 합격 기준("삭제 내용 확인 체크 전에는 다음 단계 비활성")을 따른다.

두 테스트 묶음은 고치기 전 코드에서 4개 모두 실패하고 고친 코드에서 통과하는 것을 확인했다.

#41 리뷰 반영: 탈퇴가 성공하면 로그인 상태가 바뀌어 앱이 설정 화면을 먼저 닫는다. 기기 초안 지우기가 몇 프레임 걸리는 동안 설정 화면이 사라지면, `mounted` 확인 때문에 첫 화면 처리(`onDeleteComplete`: 첫 화면 + 홈 탭)를 건너뛰었다. 화면에는 비로그인이면 항상 첫 화면이 나와서 탈퇴 직후는 정상으로 보였지만(에뮬레이터에서도 첫 화면 확인), 탭이 홈으로 돌아가지 않아 **다음에 다른 계정으로 로그인하면 탈퇴 전 탭(스케치북)에서 시작**했다. 이제 성공하면 `mounted`와 상관없이 `onDeleteComplete`를 부른다(앱 쪽 상태라 안전). 실패 경로의 `mounted` 확인은 그대로다. 앱 전체(`EselApp`)를 띄우고 초안 지우기가 몇 프레임 걸리게 한 시험 `test/app/account_delete_flow_test.dart`가 고치기 전 코드에서 실패하고 고친 코드에서 통과한다.

서버 정책 참고: 탈퇴자가 참여한 트윈은 상대 사진까지 함께 지워진다(서버 README). 상대 기록 보존 여부는 기능 목록의 사용자 결정 항목이며 이번 확인 범위가 아니다(트윈은 앱 서버 모드에서 아직 막혀 있음).


## PR #18 리뷰 반영: 화면 유지와 실패 처리

- 최초 오늘 데이터가 없을 때만 전체 로딩/오류 화면을 사용한다. 이후 새로고침 중에는 현재 화면을 유지하고 상단에 진행·오류·재시도를 표시한다. 사진 선택 뒤 앱 복귀, 날짜 변경, 조회 실패가 편집 중 사진·문구·착용 정보를 초기화하지 않는다. 실제 올리기에서는 최신 날짜·하루 한 호 규칙을 다시 검사한다.
- 새로고침 중 고른 색은 요청 완료 후 순서대로 전송한다. 다른 계정으로 바뀌면 이전 계정의 대기 요청은 취소한다. 반응 버튼도 순차 처리하고 댓글 전송만 자체 중복 입력을 막는다. 서버 응답 전 성공으로 표시하거나 로컬로 전환하지 않는다.
- 타인의 상세 제목은 `한 줄`이며 숫자를 붙이지 않는다. 본인의 제목은 조회된 댓글 페이지 길이 대신 서버 전체 댓글 수를 사용한다.
- 스케치북 추가 조회 오류는 기존 목록과 다음 cursor를 유지한다. 목록 아래 `더 보기 다시 시도`로 같은 페이지를 재요청한다.
- 서울 자정 재조회 실패 시 현재 서비스 시계의 다음 자정으로 예약하여 1초마다 반복 요청하지 않는다.
- 설정 → `기기 초안 · 초안 달력`에서 현재 계정 초안을 편집·확인 후 삭제할 수 있다. `기기 접근성 설정`은 기존 큰 글자·움직임 줄이기 설정을 연다. Android에서 중단된 사진 선택을 복구할 수 있으면 확인을 받고 현재 편집에 적용한다. 실제 OS 프로세스 종료 복구는 단말에서 추가 검수가 필요하다.
- 저장 원본과 백업이 모두 손상됐으면 앱은 안내와 재시도를 표시하며 기기 저장을 막는다. 파일을 지우거나 빈 데이터로 덮어쓰지 않는다. 파일 수리 후 재시도로 다시 읽는다. 정상 백업 복구는 기존 방식을 유지한다.
- 피드의 색 링크는 팔레트의 색상 탭을 열고, 후보 선택 목록은 선택한 후보를 먼저 표시하고 나머지 색 앞에 구분선을 둔다. 본인 스케치북은 자기 좋아요·스크랩 대신 공유를 표시한다.

### 팀 결정이 남은 사항

착용 정보 이름에는 가격·링크 대신 옷 이름을 적도록 안내하지만 새 금지 검사는 넣지 않았다. 가격/URL 문자열을 어디까지 거절할지는 팀 정책이 필요하다. 계정 정보가 없는 예전 개발 초안은 보존하고 개수만 안내한다. 특정 계정으로 자동 귀속·공개·삭제하지 않는다. 기존 접근성·달력·초안 화면을 재연결했으며 남은 미사용 화면의 삭제는 이번 변경에 포함하지 않는다.

자동 검증은 `test/app/server_editor_retention_test.dart`, `startup_storage_error_test.dart`, `test/features/server/review_regressions_test.dart`, `test/features/drafts/library_recovery_test.dart`, `photo_recovery_test.dart`에 있다. HTTP 응답 지연·실패, 앱 복귀와 날짜 변경, 계정 분리·초안 삭제 확인·파일 손상·사진 복구 선택을 재현한다. 실제 갤러리 앱·실기기·macOS/iOS 조작 검사와 구분한다.
