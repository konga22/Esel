## Flutter 버전

- 기준은 **Flutter 3.44.x 이상**(Dart 3.12)이다. `pubspec.yaml`의 `environment.flutter: ">=3.44.0"`가 막는다. `flutter --version`으로 먼저 확인한다.
- `flutter pub get`이나 `flutter test`를 돌리면 설치한 SDK에 따라 `pubspec.lock`의 SDK 고정 패키지(meta, test_api 등)만 바뀔 수 있다. 의존성을 바꾸지 않았다면 그 변경은 커밋하지 않고 `git checkout -- flutter_app/pubspec.lock`으로 되돌린다. 커밋된 lock은 3.44.0 기준이다.
- `flutter analyze`는 경고 없이 통과해야 한다(3.44.0에서 확인. 다른 버전에서 새 경고가 나오면 고치고 버전을 적는다).

## 팀원 Android 휴대폰 실행

Flutter SDK·Android SDK를 준비하고 휴대폰 USB 디버깅을 켠다. USB 연결 후 휴대폰에서 디버깅을 허용한다.
flutter_app 폴더에서 실행한다.

```powershell
flutter pub get
flutter devices
flutter run -d <휴대폰장치ID> --dart-define=ESEL_API_MODE=mock
```

저장소 루트에서 `scripts/start-demo.ps1 -DeviceId <휴대폰장치ID>`로도 실행할 수 있다.
Docker·DB·.env·OAuth 설정은 필요 없다.
설치 파일은 `flutter build apk --debug --dart-define=ESEL_API_MODE=mock`으로 만든다.
경로: flutter_app/build/app/outputs/flutter-apk/app-debug.apk.

Windows에서 symlink 오류가 나면 Windows 개발자 모드 또는 관리자 터미널에서 패키지를 준비한다.
iPhone은 macOS/Xcode·서명이 필요하며 이번 환경에서 검증하지 않았다.

> **APK를 외부에 배포하지 않는다(로컬 시연용).** 앱에 든 예시 인물 사진은 Pexels 사진이고, Pexels는 모델 초상권 동의를 보장하지 않는다(하네스 §6). 팀원 기기에 직접 설치해 시연하는 데만 쓰고, 스토어·공개 링크·메신저 파일 공유로 내보내지 않는다. 사진 출처는 [flutter_app/assets/README.md](../../flutter_app/assets/README.md).

## 웹 브라우저로 볼 때

```powershell
flutter run -d chrome --dart-define=ESEL_API_MODE=mock
flutter build web --dart-define=ESEL_API_MODE=mock
```

- `--dart-define=ESEL_API_MODE=mock`을 빼면 서버 모드의 옛 기기 보관함 화면이 뜬다. 디자인 화면을 보려면 휴대폰·웹 모두 이 옵션을 붙인다. IDE 실행 버튼은 이 옵션을 따로 설정해야 한다.
- 웹은 기기 파일을 쓸 수 없어 사진·초안·발행 기록을 브라우저 메모리에만 둔다. 새로고침하면 처음부터 다시 한다.
- 넓은 창에서는 휴대폰 폭(최대 430)으로 가운데에 보인다.
- 한글 본문 글꼴은 브라우저가 처음 열 때 인터넷에서 받는다(Noto Sans KR). 인터넷이 없으면 한글이 네모로 보일 수 있다.

## 영상 흐름

1. 첫 Esel 표지(J1)를 내려 본다. 표지는 첫 장만이고, 내리면 제호가 함께 올라가고, 다시 위로 올리면 작은 로고 "Esel."이 나타났다가 맨 위에서 제호로 녹아든다. 640px 지나면 아래에서 로그인 바가 올라온다.
2. 로그인 바 → 내 잡지 만들기(창간). 색(오늘 후보 3색) → 사진 촬영·앨범 → 제호(영문 소문자 2~10자, 예시 인물 이름은 이미 있는 이름) → 얼굴 연출 4종과 얼굴 위치 → 창간하기.
3. 창간하기에서 계정을 만든다(이메일 가입, 비밀번호 8자 이상, 또는 Apple·Google 시연 계정). 실제 인증이 아니라 이 기기 안의 시연 계정이다.
4. 창간호 화면에서 Nº 001을 확인하고 → 오늘의 표지 보러 가기.
5. 가판대(캡슐의 물감) → 오늘 발행했으니 모든 색 방이 열려 있다. 내 표지가 내 색 방에 함께 꽂혀 있다.
6. 내 잡지 → 서가 전체 보기 → 표지/책등 전환.
7. 설정 → 계정 관리 → 로그아웃 → 같은 이메일·비밀번호로 다시 로그인하면 Nº 001이 그대로다. 다른 비밀번호로는 열리지 않는다.

같은 색 잠금(P01)은 오늘 아직 발행하지 않은 계정에서 보인다. 창간하면 그날 Nº 001을 낸 것이라 그날은 모든 방이 열려 있다(DEV-06 합격 기준). 다음 날(서울 자정 이후) 같은 계정으로 가판대를 열면 오늘 후보 3색 칩에 모두 자물쇠가 붙고, 그 방은 최신 3장과 흐린 책등(개수만)으로 보인다. 후보 색을 바꿔도 열리지 않고, 오늘 호를 발행하거나 다시 자정이 지나면 열린다. 시연 데이터의 예시 인물은 매일 발행한 것으로 둔다.

- 하루 한 호, 서울 날짜 기준이다. 앱을 켜 둔 채 자정을 넘기거나 다시 열면 그날 기준으로 다시 계산한다. 반복 시연은 다른 이메일로 새 잡지를 창간한다.
- 앱을 완전히 종료하면 다시 로그인한다. 계정(비밀번호는 솔트를 붙인 다이제스트만)은 기기 보안 저장소에, 호·사진은 기기 보관함(시연 모드 전용 폴더)에 남는다. 웹은 모두 메모리라 새로고침하면 처음부터.
- 탈퇴하면 그 계정의 호·초안·사진과 내보낸 표지 이미지까지 지운다. 원본 앨범 사진은 건드리지 않는다.
