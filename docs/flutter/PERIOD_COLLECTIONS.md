# 일·주·월 표지 특집과 주간 콘텐츠 · 2026-10-18

사용자 요청으로 기존의 ‘두 콘텐츠만’ 범위를 확장했다. 월·연간 베스트나 개인 스타일 점수 결산을 추가한 것이 아니다. **일간·주간·월간 기간에 해당하는 공개 표지를 직접 고르고 선정 이유를 기록하는 로컬 특집**이다. 사용자에게 확인한 선정 방식은 로컬 직접 선정이다. 서버·DB·실제 OAuth·업로드·동기화는 구현하지 않는다. PR은 사용자 검토 전 올리지 않는다.

## 실행과 화면

기존 `flutter run -d <장치ID> --dart-define=ESEL_API_MODE=mock`을 사용한다. Docker·DB가 필요하지 않다. 기기 기록과 시연 계정은 기존 것을 유지한다. 가판대와 내 잡지에 **일·주·월 표지 특집** 진입점이 있다. 새 하단 탭은 없다.

1. 기간 단위를 고르고 이전/다음 기간을 살펴본다. 미래 기간은 이동할 수 없다.
2. ‘공개 표지 골라 특집 편집’에서 표지를 선택한다.
3. 주제에 맞는 착장·색 활용·다양한 스타일을 참고하여 선정 이유를 1~120자로 적는다. 자동 판별·점수·좋아요 정렬은 없다.
4. 특집 보기에서 표지와 이유를 읽는다. 이유 수정과 특집에서 빼기가 가능하다. 해제해도 발행본·호수는 유지한다.
5. 종료·재로그인 후 본인 편집 기록을 다시 읽는다. 다른 계정의 특집 편집 기록은 섞이지 않는다.

일간은 서울 00:00~다음 날 00:00, 주간은 월요일~다음 월요일, 월간은 매월 1일~다음 달 1일의 종료 미포함 구간이다. 선택된 표지는 발행 날짜 내림차순과 안정적인 ID 순으로 표시하고 순위를 뜻하지 않는다. 기존 사진 ID를 참조하며 사진을 복제하지 않는다. 선정한 표지가 삭제되거나 비공개가 되면 후보/특집 응답에서 제외한다. 누구나 서버 운영자의 공식 특집을 발행할 권한이 생기는 기능은 아니다. 기기 안에서 로그인한 사람이 **본인 특집을 편집하는 단계**다.

## 주간 드레스코드의 로컬 완성 범위

- 매주 공통 주제로 가방으로 포인트·겹쳐 입기·데님·비 오는 날을 순환한다. 실시간 날씨를 읽거나 외부 운영자가 주제를 배정하는 기능은 아니다.
- 주제·기간·참여 방법·내 상태 → 기존 편집/발행 또는 오늘 발행본 연결 → 내 참여 기록 → 주제별 참여 표지 보기까지 연결한다.
- 다른 참여자 표지는 **이 기기의 다른 계정에서 실제 발행하고 주제에 연결한 기록**을 읽는다. 원격 기기나 가상의 참여자 목록을 만들지 않는다. 새로 설치한 기기에서는 참여자가 없을 수 있다.
- 공개 여부를 먼저 적용한 뒤 참여/기간별로 모은다. 타인의 오늘 후보 색이 잠겼으면 콘텐츠에서는 표지·이름·ID를 반환하지 않는다. 가판대의 기존 3장 미리보기를 콘텐츠마다 새로 뽑지 않으므로 미리보기 우회도 없다. 지난 날짜·후보 밖 색·발행 후에는 기존 규칙에 따라 열린다. 비공개 반응 숫자는 노출하지 않는다.
- 같은 옷, 다른 코디는 기존의 본인 과거 발행본 선택·오늘 표지 연결·비교를 유지한다. 신규 사용자 안내·기간 종료·취소·중복·재시도·선택한 표지 삭제 처리를 재사용한다.
- 오늘 호를 삭제했더라도 하루 발행 이력은 남는다. 삭제된 오늘 호는 참여에 연결할 수 없고 새 호를 다시 발행하게 유도하지 않는다.

## 함께 보완한 저장 문제

- LocalLibrary의 version 1 JSON에 선택적인 `publicationLedger`, `reactionRecords`, `featureRecords`를 추가했다. 옛 파일도 읽고 남아 있는 발행본에서 이력을 보완한다. 기존 데이터 삭제/초기화는 하지 않는다.
- 발행 이력을 사진/표지 삭제와 분리하여 같은 날 재발행과 다음 호수 재사용을 막는다. 이전에 이미 삭제되어 어떤 파일에도 남지 않은 과거 이력까지 복원할 수는 없다. 일반 계정 탈퇴에서는 그 계정 이력도 정리한다.
- 좋아요·스크랩·구독·독자 한 줄은 계정별 로컬 저장·복원으로 바꾼다. 저장 실패 알림과 재시도를 제공한다. 서버로 상대 사용자에게 반응을 전달하거나 여러 기기에서 집계하는 기능은 아니다.
- 계정 전환·탈퇴 시 화면 및 반응 캐시를 분리한다. 날짜 계산은 기존 서울 시간 처리를 쓴다.
- 서버 모드에는 RemoteCollectionSource를 연결하며 명시적 미구현 오류를 반환한다. 서버 실패 시 로컬로 바꾸지 않는다.

## 서버 담당자와 합의할 사항 (검토안)

기존 `server/api-contract.json`의 경로·권한·오류 및 DTO/Swagger가 정본이다. 이번 작업에서 확정하지 않은 API 주소·엔드포인트·migration은 만들지 않았다.

| 대상 | 합의할 계약 |
|---|---|
| 특집 조회 | 단위(day/week/month), 서울 시작/종료, 특집 ID·버전·운영 상태, 허용된 표지와 선정 이유. 공개 필터 후 목록 구성 |
| 선정/수정/해제 | 운영자/편집자 권한, 선정 기준, 공식 발행·검토 절차, 버전 충돌·중복 방지·감사 기록. 로컬 본인 편집과 구분 |
| 주간 주제/참여 | 서버 운영 주제와 기간 ID, 인증 주체에서 소유권 결정, 오늘 호/하루 한 호 검사, 같은 옷 관계, 발행과 참여의 원자성 |
| 이미지/공개 | 잠금·차단·삭제·미성년자·접근 권한을 이미지 URL까지 적용. 숨긴 ID·이름·사진·비공개 반응 수 제외 |
| 오류 | 인증 만료·권한 없음·기간 종료·자원 삭제·충돌·저장 실패. 기존 오류 봉투/코드 체계로 합의 |
| 데이터 이전 | 로컬 특집과 반응 기록의 업로드 여부, 충돌·동기화·재시도·권한 재검증. URL만 바꾸면 끝나는 작업이 아님 |

## 검증과 한계

Flutter의 기간/공개 필터/삭제 이력/반응 영속성 검사와 화면 위젯 테스트로 선정·해제·오류 재시도·작은 화면·글자 200%·뒤로가기를 검사한다. 사용자의 컴퓨터 조작 중단 요청에 따라 마우스/키보드/창 활성화·에뮬레이터 직접 조작은 하지 않는다. 생성한 목업 CL1 캡처는 구성 참고용이고 실기기 화면을 검수한 증거가 아니다. macOS·iOS·물리 휴대폰·실제 서버 연동은 미검증이다.
