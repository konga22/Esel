# 서버 PR 리뷰 체크리스트 (멘토용)

팀원의 서버 PR을 볼 때 쓰는 목록이다. 위에서부터 보면 중요한 문제를 먼저 잡는다. 자동 검사가 잡는 것은 확인만 하고, 사람이 봐야 하는 것에 시간을 쓴다.

## 1. 먼저 자동 검사

- [ ] PR 설명에 `npm run check:server`, `lint`, `test`, `test:e2e`, `build` 결과가 있고, 못 돌린 것은 못 돌렸다고 적혀 있다.
- [ ] 직접 한 번 돌려 본다: `cd server && npm run check:server`(설치 없이 됨).
- [ ] PR에 AI의 **학습용 보고**(만든 것·이유·새 개념·확인법·결과·남은 것)가 붙어 있다.

## 2. 약속(api-contract.json)

- [ ] 새로 만든 API가 모두 `api-contract.json`에 있고, 주소·방법·access·응답 이름이 그대로다.
- [ ] 약속 자체를 바꿨다면 PR 설명에 "무엇을 왜 바꾸자는지"가 있다. 앱 쪽 영향(화면, `docs/dev/FEATURES.md`)을 같이 봤다.
- [ ] `done`으로 바꾼 API는 `test/contracts/`의 todo가 실제 테스트로 바뀌었다.

## 3. 사람이 봐야 하는 위험

- [ ] **숫자 공개(P18)**: 남이 부르는 응답에 좋아요·구독자·한 줄·스크랩 수가 없다. `…OwnerDto`는 주인 확인 뒤에만 나간다.
- [ ] **잠금(P01)**: 잠긴 표지의 ID·이름·사진 주소가 어떤 응답에도 없다. 숨긴 것은 404다.
- [ ] **권한**: `owner`·`member` API에서 주인·참여자 확인을 서비스가 한다. 다른 사람 ID로 부르는 테스트가 있다.
- [ ] **하루 한 호(P04)·동시 요청**: DB 제약이나 트랜잭션으로 막았고, 두 요청을 동시에 보내는 테스트가 있다.
- [ ] **날짜**: "오늘"을 서버가 `SERVICE_TIME_ZONE`으로 정한다. 앱이 보낸 날짜를 믿지 않는다.
- [ ] **비밀값**: 비밀번호·토큰 원문을 저장하지 않는다. 로그에 토큰·비밀번호를 찍지 않는다.
- [ ] **새 패키지·외부 서비스**: 추가했다면 이유가 있고, 팀이 승인했다.
- [ ] **migration**: 새 파일로 추가했고, 이름이 무엇을 바꿨는지 드러낸다. 공유된 파일은 그대로다.

## 4. 읽기 쉬움

- [ ] 컨트롤러는 짧고(받기·부르기·돌려주기), 규칙은 `…rules.ts`의 이름 있는 함수에 있다.
- [ ] 오류는 `AppException('코드')`로 던지고, 코드가 `api-contract.json`에 있다.
- [ ] 테스트 이름만 읽어도 무엇을 보장하는지 알 수 있다.

## 5. 이해했는지 묻기

코드를 고치게 하기 전에 하나씩 물어보면 배움이 오래 간다.

- "이 API가 401이 아니라 404를 돌려주는 경우는 언제야? 왜 그렇게 했어?"
- "발행 중간에 서버가 꺼지면 호수는 어떻게 돼?"
- "이 응답을 다른 사람이 받으면 무엇이 보여?"
- "이 migration을 이미 받은 사람 DB에는 무슨 일이 일어나?"
- "이 테스트가 실패하려면 코드를 어떻게 망가뜨려야 해?"

## 6. 리뷰 댓글 쓰는 법

- 문제 → 이유(어떤 약속·계약) → 고치는 방향 순서로 한 줄씩. 예: "공개 응답에 likeCount가 있어요 → P18(숫자는 본인에게만) → IssueOwnerDto로 옮기고 /api/me/issues/:id/reactions에서만 돌려주세요."
- 꼭 고칠 것과 다음에 해도 되는 것을 나눠 적는다.
