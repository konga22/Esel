## 만들기와 게시

저장소 루트에서:

```bash
npm run mockup:build
```

- `src/shell.html`(스타일·틀)과 `src/app.js`(화면·상태)를 합쳐 `dist/index.html`을 만들고, 사진과 물감을 `dist/img/`에 복사한다. 물감은 macOS `sips`가 있으면 480px로 줄인다.
- `node .codex/temp/prototype/20261011-app-mockup/build.mjs --local`은 게시 환경과 같은 문서 틀을 씌운 `dist/_local.html`도 만든다. `python3 -m http.server --directory .codex/temp/prototype/20261011-app-mockup/dist`로 띄워 확인한다.
- `dist/`는 git에 올리지 않는다. 게시본을 갱신할 때는 `dist/index.html`과 `dist/img/*`를 같은 아티팩트 주소에 다시 올린다.

## 지킨 규칙

- 같은 색: 올리기 전에는 그날 후보 3색 방이 모두 최신 3장만 보이고 나머지는 이름·사진 없이 흐린 칸과 개수만 보인다. 색을 바꿔도 열리지 않고, 후보가 아닌 색은 열려 있다. 올리면 모두 열리고, 미성년자는 잠금이 없다(P01). 트윈 게시나 색 복원으로는 열리지 않는다(P03, P09). 홈·팔레트 추천·구독 격자에서도 올리기 전에는 후보 3색 사진을 뺀다.
- 숫자: 좋아요·저장·한 줄 수는 내 캔버스에서만 보인다(P18). 남의 스케치북·팔레트 칸에는 반응 숫자가 없다.
- 하루에 한 번만 올린다(P04). 비로그인은 첫 표지와 안쪽 2쪽까지이고, 반응·구독·만들기는 로그인 시트를 연다(P12).
- 얼굴: 자르기는 하나만, 물감 한 획은 따로 켜고 끈다. 목 아래를 고르면 물감이 꺼지고 버튼이 눌리지 않으며, 다른 자르기로 바꿔도 물감을 자동으로 다시 켜지 않는다. 사인 뒤로를 고른 사람의 사진은 안쪽 지면·스케치북에서도 사인을 얹어 얼굴을 가린다(P15).
- 착용 정보: 옷 종류·이름(브랜드는 선택)·메모·오늘의 색 옷만 남긴다. 가격·링크 칸이 없다(P19).
- 사인은 영문 소문자 2~10자이며, 이미 있는 이름은 거른다(P14). 피그마 S2의 "이름 2–20자"는 이 규칙과 달라 하네스 규칙을 따랐다.
- 트윈은 내 후보 3색과 상대 후보 3색 중 겹치는 색이 하나이고, 서로 다른 색을 골라도 된다. 두 사람이 모두 게시해야 열리고, 공동 공개는 두 사람이 모두 동의해야 한다(P08, P10).
- 상대방의 행동이 필요한 단계(초대 수락, 게시 도착, 공개 동의)는 빗금 무늬와 `시연` 표시가 붙은 버튼으로만 넘긴다. 실제 앱에서는 서버가 확인한다.
- 팔레트 칸·작은 표지에서 얼굴 연출이 "그대로"이면 사인을 줄여 얼굴을 덮지 않게 한다(P15).
- 움직임은 04 모션 보드의 값만 쓴다. 사인 녹아들기·작은 로고·누름·로그인 바·시트·올리기 도장·같은 색 열림·하트를 쓰고, 화면 전환은 움직이지 않는다. 움직임 줄이기 설정에서는 바로 바뀐다.

## 예시 데이터로 채운 것

- 사진은 사람마다 한 장뿐이라, 스케치북의 지난 캔버스는 같은 사진을 다른 자르기(물감·디테일·목 아래·흑백)로 보여 준다. 얼굴을 가린 사람은 지난 캔버스에서도 얼굴이 드러나지 않는 자르기만 쓴다. 최근 6장만 그리고 나머지는 한 줄로 줄였다.
- 내 스케치북의 지난 캔버스 색은 색 달력의 기록(9월 1·2·4·5일)과 같다.
- 팔레트 추천 순서와 색 목록의 "오늘 많이 고른 순"은 캔버스 생성기와 같은 고정 순서다. 실제 정렬 기준은 서버가 정한다.
