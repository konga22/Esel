# 앱 목업 (2026-10-11)

휴대폰에서 링크 하나로 열어 실제 앱처럼 눌러 보는 Esel 목업이다. 캔버스의 C1–C8·J1–J7 화면과, 팀원이 피그마에 정리한 추가 기능(내 잡지·월간 색 기록·트윈·친구·설정·공유)을 [디자인 보드](../../../../docs/design/README.md) 문법으로 다시 그려 한 앱으로 이었다.

- **게시본**: `harness.json.appMockup.artifact` (비공개 링크. 공유 전에는 소유자만 열 수 있음)
- **목업일 뿐이다**: 사진·이름·숫자·날짜(2026-09-06)는 예시다. 로그인·저장·공유·카메라는 실제로 일어나지 않고, 새로고침하면 처음 상태로 돌아간다.
- **데이터 원본**: 인물·얼굴 위치·12색은 캔버스 생성기 `lib.mjs`에서 빌드 때 주입한다. 값을 이 폴더에서 따로 고치지 않는다.

## 만들기와 게시

저장소 루트에서:

```bash
npm run mockup:build
```

- `src/shell.html`(스타일·틀)과 `src/app.js`(화면·상태)를 합쳐 `dist/index.html`을 만들고, 사진과 물감을 `dist/img/`에 복사한다. 물감은 macOS `sips`가 있으면 480px로 줄인다.
- `node .codex/temp/prototype/20261011-app-mockup/build.mjs --local`은 게시 환경과 같은 문서 틀을 씌운 `dist/_local.html`도 만든다. `python3 -m http.server --directory .codex/temp/prototype/20261011-app-mockup/dist`로 띄워 확인한다.
- `dist/`는 git에 올리지 않는다. 게시본을 갱신할 때는 `dist/index.html`과 `dist/img/*`를 같은 아티팩트 주소에 다시 올린다.

## 지킨 규칙

- 같은 색: 발행 전에는 최신 3장만 보이고 나머지는 이름·사진 없이 개수만 보인다. 발행하면 모두 열린다(P01). 트윈 게시나 색 복원으로는 열리지 않는다(P03, P09).
- 숫자: 좋아요·스크랩·독자 한 줄 수는 내 표지에서만 보인다(P18).
- 하루에 한 호만 발행된다(P04). 비로그인은 첫 표지와 안쪽 2쪽까지이고, 반응·구독·만들기는 로그인 시트를 연다(P12).
- 제호는 영문 소문자 2~10자이며, 이미 있는 이름은 거른다(P14). 피그마 S2의 "이름 2–20자"는 이 규칙과 달라 하네스 규칙을 따랐다.
- 트윈은 내 후보 3색과 상대 후보 3색 중 겹치는 색이 하나이고, 서로 다른 색을 골라도 된다. 두 사람이 모두 게시해야 열리고, 공동 공개는 두 사람이 모두 동의해야 한다(P08, P10).
- 상대방의 행동이 필요한 단계(초대 수락, 게시 도착, 공개 동의)는 빗금 무늬와 `시연` 표시가 붙은 버튼으로만 넘긴다. 실제 앱에서는 서버가 확인한다.
- 작은 표지에서 얼굴 연출이 "그대로"이면 제호를 줄여 얼굴을 덮지 않게 한다(P15).
- 움직임은 04 모션 보드의 값만 쓴다. 제호 녹아들기·작은 로고·누름·로그인 바·시트·발행 도장·같은 색 열림·하트를 쓰고, 화면 전환은 움직이지 않는다. 움직임 줄이기 설정에서는 바로 바뀐다.
